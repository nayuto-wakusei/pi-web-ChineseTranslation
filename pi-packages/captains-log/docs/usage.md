# 使用船长日志

在当前机器和工作区选择普通会话，打开“船长日志”，点击“让船长转述”。伴随扩展读取源会话当前分支最新已完成的助手文本回复，不发送提示、不修改源转录。独立的船长会话使用你配置的模型转述文本，以海盗船长的风格保留事实、警告、下一步以及原始代码和命令。

船长首次收到角色介绍；后续请求复用仍由 daemon 承载的船长会话。只有在发送请求前明确确认旧船长未被承载时才自动创建新会话，不因超时或任意连接失败重试、重发或替换会话。daemon 重启后，如需保留旧船长的上下文，先在会话列表打开最近的船长日志会话，等待加载完成，再选择需要转述的源会话。

## 结果与连接

- “打开源会话”按照记录的机器、项目、工作区和源会话 ID 返回聊天。目标不可用时显示常规错误，不自动创建替代会话。
- 结果支持 Markdown 标题、列表、强调、链接、表格和代码块。内嵌 HTML 按文本显示，危险链接不可点击，图片不会自动加载。“历史转述”和“诊断”默认折叠。
- 打开面板或选择“打开船长转述”不会消耗模型令牌。只有点击转述按钮才提交任务。
- 浏览器使用双向 peer 通道接收后端进度，无轮询。连接或重连会读取快照；进度不是逐令牌输出，船长完成后才收到最终转述。
- 关闭面板或浏览器不会取消已被后端接收的工作。重新连接可恢复结果；接收状态不确定时绝不自动重发。

## 无法运行时

源会话必须属于当前机器和工作区，未归档、非临时会话，且不是船长本身。等待源会话空闲，并确保当前分支存在已完成的助手文本回复；未完成、中止、失败及仅包含工具调用的回复不能转述。现有会话缺少伴随扩展时，执行 `/reload` 后重试。

每个工作区同时只运行一个面板转述任务。船长忙碌、转述时直接向其发送其他消息、提供方错误、中止或截断回复、运行时替换均报告失败，不当作成功。接收超时或完成超时仅移除监听，不停止 Pi；不确定请求须先检查船长会话再手动重试。过大的源回复或结果会被拒绝，不静默截断。

转述和元数据保存在宿主提供的插件数据目录，按项目和工作区隔离。会话转录仍由 Pi 管理。中断记录保留，但没有持久任务恢复或自动清理策略。源文本会发送给船长使用的模型提供方；此代码受信任，不提供工具沙箱。

## 安装与激活

在目标机器“设置 → Pi 包 → 可用包”中安装，再到“设置 → PI WEB 插件”显式启用。本包已编译；手动安装可用 `pi install /absolute/path/to/dist/pi-packages/captains-log`。

从承载会话之外手动重启目标 session daemon，再刷新浏览器。仅重启 Web/API 不能激活后端。现有会话执行 `/reload` 加载或更新伴随扩展；项目级包仍须经过正常的项目信任流程。

禁用 PI WEB 插件仅控制面板和后端，不移除原生扩展。移除 Pi 包会移除两种资源声明，但保留会话与插件数据。旧 Workspace Reviews 示例拥有独立插件 ID，须另外禁用或移除。
