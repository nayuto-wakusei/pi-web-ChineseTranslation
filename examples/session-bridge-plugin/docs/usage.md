# 使用工作区审查

## 在所选机器安装

本目录是独立本地 Pi 包，不是默认功能。在持久目录运行 `npm install` 和 `npm run build`，然后通过执行审查的机器的“设置 → Pi 包”安装绝对目录。不要再向 PI WEB 插件目录链接另一份副本。

手动配置时，保留既有条目，并在该机器 daemon 实际使用的 Pi profile 的 `packages` 中增加目录：

```json
{ "packages": ["/absolute/path/to/session-bridge-plugin"] }
```

`pi install /absolute/path/to/session-bridge-plugin` 修改 CLI 当前 profile，只有它与 daemon 使用相同 profile 时才适用。项目本地安装 `pi install -l ...` 需要普通模式项目信任。原生资源筛选中须保留 `src/companion.ts`；PI WEB 发现 `piWeb.plugins`，Pi 独立加载 `pi.extensions`，只启用后端不足以工作。

在可中断会话时，从 daemon 托管会话之外手动重启目标 daemon，然后刷新浏览器。远端机器须在该机器安装、构建和启用，再在 PI WEB 选择它。本例的构建和测试不会安装或重启承载实例。

最低平台版本见 `package.json`。未发布的 PI WEB 应先构建打包，在此独立示例安装 tarball 替代注册表依赖。本包保留 `private` 防止误发布；构建目录可单独安装，`npm pack` 可归档。发布者可自行选择包名，显式移除 `private` 并发布构建包。

## 审查与浏览

1. 在目标项目配置模型和凭据。
2. 选择项目和工作区，打开“审查”。
3. 点击“开始审查”并处理正常启动和信任提示。每个工作区同时只受理一个审查，新建专用会话，不向既有选中对话注入提示。
4. 点击“刷新审查”查看进度，在会话列表按完整 ID 查看流式输出、提供器错误或取消。刷新是手动的；切换工作区或刷新浏览器不会停止已受理的审查。
5. 从“已保存的审查”选择记录，或使用上一条 / 下一条按钮。结果按转义后的纯文本显示，不执行 HTML，也不渲染 Markdown。

固定提示要求检查暂存、未暂存和相关未跟踪源码及周边代码；没有改动应明确说明。报告包含实际缺陷、文件行号、影响、建议和局限，不修改文件。它不比较可配置分支或提交、不执行修复，也不保证覆盖完整。工作区不是冻结的 diff，需要一致目标时请避免边审查边改代码。

“已完成”表示对应请求正常结束、产生非空最终助手文本并由后端保存，不代表没有缺陷或质量认证。提供器错误、中止、工具失败、截断或空最终响应、其他用户提示干扰都会保守地判为失败，即使后续自动重试产生文本。审查完成前不要向专用会话追加或排队消息。

“失败”记录保存原因，不把部分结果当作成功。伴随扩展回执等待 5 秒，最终结果等待 10 分钟。重试前检查扩展启用、信任、凭据和实际对话；不自动重试。连接关闭、超时和浏览器断连不会停止代理，需要停止时在会话中操作。

后端重启后遗留的运行记录显示为“已中断”，不冒充完成。没有事件重放、重新连接或崩溃恢复结果；请检查会话，必要时显式开始新审查。捕获期间的会话 reload/shutdown 也使审查失败。请求受理后浏览器报错，应先刷新列表，避免重复发起。

## 存储与所有权

后端在所选机器宿主提供的 `dataDirectory` 下拥有 JSON 文件。目录名为宿主解析的 project/workspace ID 的 SHA-256，文件名为生成 UUID。记录包含创建时间、完整会话 ID、状态及最终结果或失败文本。历史按 ID 而非路径归属；删除再创建身份不会重分配旧记录。

写入使用独占私有临时文件、文件同步和原子 rename；目录和文件拒绝符号链接。peer 输入只能选择验证后的审查 ID，不能选择任意路径。读取验证记录，损坏时明确失败。不使用额外宿主状态存储、项目配置或助手生成的结果路径。写入失败在后端存活时通过刷新和日志报告；随后退出则最后的持久运行记录显示为中断。

先保存运行记录，再创建会话，再写入会话 ID；创建和 ID 写入之间崩溃可能遗留空 ID，需要在会话列表找到新对话。这不是事务性持久任务队列。

结果限 48,000 个 JavaScript 字符，提示要求少于 12,000。超限报错，不静默截断。列表仅返回元数据，按 ID 单独读取文本。小型档案刷新时扫描文件，没有分页、保留策略、删除 UI、自动迁移或多进程写协调。需要备份或裁剪时离线处理插件文件，不能让两个后端共享同一目录。内容可能包含敏感代码，不加密；原子可见性不保证抵御所有断电情形。

## 原生 Pi 与宿主边界

- 浏览器仅使用所选机器的 `context.peer`。状态按 machine/project/workspace 分键，迟到响应不会污染其他范围；浏览器入口和共享协议都位于 `browserRoot` 内，支持嵌套部署。
- 服务端在 `start()` 解析两个公开会话能力，在宿主解析的工作区内创建会话，再独立连接。已受理任务属于插件 lifetime，不属于短浏览器请求。dispose 通过 lifetime 取消捕获，但不拥有宿主会话。
- 伴随扩展使用原生 `pi.sendUserMessage`、`before_agent_start`、消息和工具 hook、`agent_settled`。生成请求 ID 出现在启动提示和回复事件中；后端先订阅后发送。回执和完成独立，`agent_end` 后可能还有重试和压缩，不能作为完成。
- 伴随扩展不创建独立 SDK runtime，也不写存储。离开 PI WEB 可以无害加载，但没有面板和后端来请求或保存审查。

这是可信作者工具，**不是只读沙箱**。“不修改文件”只是模型指令，普通 Pi 工具、项目指令和安装的扩展仍拥有原权限。需要权限强隔离时不能依赖此提示。其他扩展可影响模型并在同一原生总线发送事件；协议只关联协作事件，不是对恶意扩展的认证。

发现、能力、peer 限制、信任与生命周期见[插件指南](../../../docs/plugins.md)。源码为严格 TypeScript，示例构建对原生 Pi 依赖声明使用 `skipLibCheck`；仓库已安装包冒烟另行启用完整库声明检查，验证独立浏览器与后端消费者。
