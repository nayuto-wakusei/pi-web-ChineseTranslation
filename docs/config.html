作用域： “机器”为联邦中所选机器；“网关”为服务当前浏览器的机器；“项目”为同一仓库的全部工作区。

重启： “Sessiond”为会话守护进程。重启可能中断活跃会话，Web/API 重启或浏览器刷新不能代替。

配置文件与优先级

设置目标与草稿

普通模式的设置对话框独立持有“配置机器”选择，只改变机器级设置的目标，不切换正在使用的项目、工作区或会话。网关配置、默认主题和快捷键仍属网关，浏览器主题覆盖仍属设备。存在未保存的文件访问或上传草稿时，切换设置机器前需确认放弃或继续编辑；管理模式不开放这套普通跨机器选择器。

通用设置分别持有网关与目标机器草稿：配置刷新只更新未编辑字段，不用其他机器的值重设当前草稿；保存返回的配置确认已提交值后，才结清对应提交，保存期间的新编辑仍保留。快捷键按操作行确认保存值，只清该行已提交且未再改动的草稿；回调结束本身不是保存确认，也不清其他行草稿。

选择配置位置
位置 用途 路径 / 编辑方法
机器配置 一台机器上的 PI WEB 设置。 设置界面或 ~/.config/pi-web/config.json。可用 PI_WEB_CONFIG覆盖，否则 XDG_CONFIG_HOME 改变配置根目录。
项目配置 共享文件访问和上传/附件目录。 <project>/.pi-web/config.json，可随仓库提交。
Pi 设置 共享 agent 设置、Pi 包与默认会话存储；普通认证、模型与偏好另按项目管理。 ~/.pi/agent 为默认目录，与 PI WEB 配置分离，参见 代理存储。
托管状态 PI WEB 注册表、归档及项目认证/偏好。 ~/.pi-web 为默认值。 不是 用户可编辑配置 API，参见 存储。

机器优先级： 内置默认值 → 全局配置 → 环境覆盖（最高）。

  "version": 1,
  "uploads": { "defaultFolder": "manual/uploads" },
  "attachments": { "defaultFolder": "prompt-attachments" }

自定义配置路径：服务命令与恢复

start, restart及 doctor 就绪检查默认使用安装服务保存的配置路径，除非调用者指定非空 PI_WEB_CONFIG 覆盖。 doctor 检查受管理安装，不代表所有自定义环境。

自定义路径：情况与处理
情况 行为 / 操作
使用安装路径 执行 pi-web start, pi-web restart或 pi-web doctor 。
单次命令覆盖 调用时指定非空 PI_WEB_CONFIG ，不重写服务定义。
更改服务配置路径 执行 pi-web install --config /path/to/config.json ，重新生成 Web/API 与 daemon 服务。
旧安装仅 Web 设置路径 重跑同一安装命令，使两进程使用同一配置。
systemd 无法验证已加载服务环境 管理器状态过期、加载 fragment 不同或管理值无法验证时失败，不猜测。受管理 Environment= 值（当前 PI_WEB_CONFIG）须与安装定义一致；无关变量忽略，未改管理值的 drop-in 允许。
systemd 使用 EnvironmentFile= 本地保留严格检查：文件内容不在 systemctl 的 Environment 属性内，无法验证文件覆盖时失败，不采用仅警告策略。
launchd 使用旧路径或其他 plist 标签 start 和 doctor 失败； restart 重新加载已安装 plist，可修复过期状态。

应用主题与发送默认值

defaultTheme 是网关配置，形如 { "themeId": "plugin-id:theme-id", "auto": true }：themeId 必须为限定贡献 ID，auto 必须为布尔值。auto: true 在该主题有明暗配对时跟随系统明暗，否则使用所选主题。浏览器设备已保存的主题覆盖优先；主题暂不可用时使用回退，不删除原选择。主题属于整个应用，不保存到当前远端机器；保存/刷新配置后生效，无需重启 daemon。

在 设置 → 通用 → 主题 中，“在此设备使用”保存浏览器覆盖，“设为默认”保存网关默认且不覆盖已有设备选择，“使用默认值”清除此浏览器覆盖。Auto 只在主题有明暗配对时跟随设备。

网关 defaultStreamingBehavior 为 "steer"（默认）或 "followUp"，决定流式工作期间编辑器的默认发送方式，不改变已在 daemon 中排队的消息。浏览器分区尺寸、编辑器偏好与普通导航顺序不是新的项目配置文件；导航顺序是按机器管理的托管状态，管理模式不共用普通存储。

会话命名与归档

机器配置 sessionNaming 仅接受以下可选字段，不提供项目覆盖。设置保存后用于后续命名请求，无需重启；每次请求固定自己的有效设置，不覆盖用户已命名会话，也不切换聊天模型。

字段 默认值 约束
model 当前会话模型 精确 provider/model-id；使用原会话普通项目或管理 registry
maxTokens 24 正安全整数
thinkingLevel minimal 已知思考等级；off 不发送 reasoning 参数
timeoutMs 10000 总耗时，整数 1..2147483647 毫秒

模型不可用、超时或命名失败时使用首条消息的回退名称；标题语言跟随用户请求。命名设置不把项目凭据切换为全局凭据。

sessionArchive.directory 选择新归档内容目的地，非空环境变量 PI_WEB_SESSION_ARCHIVE_DIR 优先；默认 $PI_WEB_DATA_DIR/archived-sessions。配置路径或环境路径相对进程 cwd 解析为绝对路径，daemon 启动后固定，修改需重启 daemon。归档索引仍是 $PI_WEB_DATA_DIR/archived-sessions.json，已有记录继续指向原归档文件，不自动迁移。备份时覆盖索引、旧目录与新目的地，不只复制默认目录。

MCP 设置与认证

设置 → MCP 管理所选机器当前非归档会话中已启用、支持 OAuth 的 MCP 服务器认证；先选择可写、空闲且可信的会话。服务器配置由 Pi 的全局/项目设置和信任规则决定，这里不新增 pi-web MCP 服务器配置键，也不替代管理模式的 Workbench 受控 MCP 集成。

也可从操作面板选择 MCP 登录/注销，再选择服务器；设置页直接针对所选服务器。两者使用同一独立认证流程，不切到聊天；禁用、header 认证或 stdio 服务器不列为 OAuth 候选，同机器同时只能进行一项 MCP 认证操作。

专用认证仅支持所选 Pi 1.3.0 同一 SDK 的内部凭据适配，未知版本不保证兼容。普通项目与管理使用独立私有 MCP 凭据，不回退共享 agent 的 MCP OAuth 存储；完整特权仍是管理身份，受限管理不提供该流程。认证固定原机器、会话、cwd、项目和 scope，切换选择不会转移流程。注销删除对应保存凭据，影响使用该凭据的其他会话，但不禁用服务器或撤销提供方授权。详见认证与模型。

路径格式、覆盖与目录规则
  • 外部根： 现有目录的绝对路径或 ~，例如 /opt/reference, ~/SDKs，Windows 宿主也可用 Windows 绝对路径。不支持相对根，拒绝符号链接逃逸。
  • 上传/附件目录： 非空工作区相对目录。绝对路径与 .. 逃逸拒绝；规范化重复分隔符与反斜线。
  • 上传： 创建父目录，默认保留已有文件；审核对话框可显式覆盖，直接拖放不覆盖。
  • 仅上传对话框： 清空目录可把该批次上传到工作区根。
  • 附件 API： 显式请求目录优先于配置默认值。

独立会话与跟踪子会话
  • 独立： 在同项目工作区发起工作，不向父会话回传输出。
  • 跟踪： 在父工作目录运行；完成唤醒父会话并提供输出，无需轮询。
  • 模型： 两工具都接受精确 provider/model-id，否则继承父模型；思考等级继承并限制到模型能力。
问题表单与扩展对话框不同
  • 问题表单： 最多 20 问，每问最多 12 选项，有自定义文本且可跳过。普通消息取消开放表单，新表单替代旧表单。
  • 持久性： 所属 daemon 活跃时开放表单跨浏览器/Web 重启保留。
  • 扩展对话框： 始终支持，不取决于 askUser；扩展与 daemon 超时取较早期限。
  • 超时结果： false 用于确认； undefined 用于选择 / 文本输入。

离线插件恢复
命令 效果
pi-web plugins disable <plugin-id> --restart 持久禁用，拒绝必需终端。
pi-web plugins safe-start show 检查安全启动状态。
pi-web plugins safe-start set bundled-only --restart 跳过外部服务端包，保留内置插件。

联邦兼容与不可用插件界面
  • 网关与目标一起升级，不支持混合版本。
  • 重启更新的 Web/API 和目标 daemon，再刷新。
  • 包/设置与实际服务端不匹配或服务端不健康/不兼容时，暂缓配套浏览器入口。

管理工具与特权

受限管理会话默认可使用工作区内的 Bubblewrap bash，仅挂载工作区及必要只读运行库，默认断网；沙盒不可用时拒绝执行。非空 tools.allow 须包含 bash，显式 tools.deny 仍有效。单项签名特权仅在 managementEmbed.allowPrivileged 为 true 时生效：bash 授权可增加宿主路径只读可见性；网络授权不扩大文件可见性。

机器允许特权且签名同时授予 privileged.bash 与 privileged.network 时，代理按普通模式加载工具与资源，不应用管理 allow/deny、沙箱或工作台只读能力指令，不强制同步管理 Skills。管理嵌入会话直接通过项目信任，无需普通页面预先批准，也不改写普通模式的信任决定。平台注入及与签名上下文明确匹配的旧 AGENTS 指令不加入系统提示，但不删除文件或用户自编指令；操作者的普通权限配置保留。这不授予操作系统管理员权限。

daemon 所有权标记更新使用短时互斥目录 sessiond-owner.json.lock，不会按年龄自动抢占。更新期间进程崩溃后，须确认没有 daemon 正在启动或停止，才可删除该残留空目录并重试。升级此保护机制时，先完整停止旧 daemon，再启动新版本。

管理身份、独立认证与偏好、审计和子会话管理上下文保留，浏览器交互终端仍有独立授权。修改机器特权开关需让 Web/API 与 daemon 使用同一配置并重启两者。详见 Workbench 集成。

项目插件设置

支持项目设置的服务端插件可读取注册项目根目录的 .pi-web/config.json 中 plugins.<id>.settings，不是各 worktree 独立配置。项目顶层设置键覆盖机器值，嵌套对象整体替换而非深合并；enabled 仍只属于机器配置，项目声明会被拒绝。修改服务端插件的全局或项目设置后，手动重启目标 daemon。

Git 工作树发现通知

Git 插件的 plugins.git.settings.workspaceDiscoveryHooks 为布尔值，默认 true，项目值覆盖机器值。支持命名 hooks 的 Git（2.54+）可安装自身命名通知，保留已有 hooks 且不修改 core.hooksPath；不支持时仍可按需刷新列表。通知仅提示宿主重新查询当前提供器，不直接注册工作区。修改后重启 daemon，浏览器刷新不能更新 hook 状态。

多实例可用 daemon 环境变量 PI_WEB_INSTANCE_NAMESPACE 区分通知身份：1–32 个字母、数字、下划线或连字符，首字符为字母或数字；生产默认留空，开发实例使用 dev。名称应保持稳定；退役旧名称时先在旧名称下禁用发现 hooks 并重启完成清理，再切换名称。不自动接管或迁移其他实例/旧名称的 hook。

中文语言插件

内置 zh-cn 默认启用；在有效机器配置设置 "plugins": { "zh-cn": { "enabled": false } } 可恢复英文。缺失词条回退英文，不新增语言选择器或配置文件。

浏览器使用网关机器的语言，不随所选远端机器切换。CLI 与服务端各自读取所属机器配置；远端提示原样保留，不翻译用户内容、模型回复、第三方输出、命令、错误码或协议字段。

修改后刷新网页、下次启动 CLI，并重启 pi-web-sessiond.service 及 Web 服务（开发安装为 pi-web-ui-dev.service），确保二者使用相同有效 PI_WEB_CONFIG。不支持运行中热切换。

受限管理 Skill 同步

受限管理会话只加载所属项目允许范围内的 Skills；SDK 同名去重时恢复被全局副本遮蔽的授权项目版本。启动和 /reload 同步随当前 SDK 适配的 relay、relay-runner 模板。

.pi/skills/relay/ 与 .pi/skills/relay-runner/ 为平台保留目录，旧内容会更新，其他自定义 Skill 不覆盖。普通模式及完整特权管理模式不执行此同步，保持现有资源加载行为。

完整特权管理会话在启动和 /reload 时，仅清理匹配当前模板或已知历史模板的原样项目 Relay 副本，改由已启用的内置包提供技能。目录必须仅有普通文件 SKILL.md；修改过的内容、额外文件、符号链接及其他自定义 Skill 保留，真实同名冲突仍会提示。普通模式不执行此清理。

取消特权后，下次创建或重载受限管理会话会重新下发当前模板；旧特权会话不会自动降权，应停止使用并通过新的授权入口进入。升级需重启 pi-web-sessiond.service，现有授权与沙箱规则不变。
