# 代码库维护文档

本手册面向 PI WEB 中文分支的代码维护者。目标是快速回答：行为由谁负责、状态存在哪里、改动会影响哪些边界、用什么测试证明没有回归。按渐进式披露组织，不要求先通读全部实现。

## 从这里开始

1. 初次维护：阅读[维护者上手](getting-started.md)，建立本地检查环境。
2. 理解全局：阅读[架构与状态归属](development/architecture.md)，定位进程和调用链。
3. 处理具体问题：进入 `modules/`，先读维护契约，再按需读行为细节；管理模式另见 `admin/`。
4. 准备修改：使用[改动联动与验证地图](development/change-guide.md)，确认契约、测试及重启范围。
5. 查精确字段：使用[配置参考](config.md)、[插件指南](plugins.md)和各篇末尾源码链接，不复制另一套配置表。

```text
docs/
  maintenance.md        总览与阅读路线
  getting-started.md     维护者最短上手路线
  development/          架构、跨模块改动与验证地图
  modules/              模块职责、契约、行为与源码入口
  admin/                管理集成、审计与运行维护
  config.md / .html      配置权威参考与网站版本
  plugins.md / .html     插件权威参考与网站版本
  development-checks.md 开发交付检查
  verification.md       本次文档核验记录

```

网站的安装、机器与 FAQ HTML 页面继续保留原路径。历史合并/审计记录保留供追溯，不作为当前架构的权威依据；源码目录中的包示例 README 和 agent 技能属于各自组件契约，不复制成另一份维护手册。

## 先理解四层对象

```text
Machine 机器
  Project 注册项目目录
    Workspace 工作目录（例如 Git worktree）
      Session 对话及其 Pi 运行时
```

浏览器连接的机器是网关，当前选择的工作机器可以是另一个远端。相同 `sessionId` 或 `workspaceId` 在不同机器上不代表相同对象。排障时至少记录机器、项目、工作区与会话，而不是只提供一个 ID。

典型操作：选择机器 → 添加项目 → 检查信任 → 选择工作区 → 配置模型认证 → 新建会话 → 发送任务 → 检查文件/Git/终端结果。浏览器断开不等于任务停止；重启会话守护进程则可能中断任务。

## 文档与验证范围

各模块先说明职责、调用链、状态归属和修改约束，再提供行为背景、排障与源码/测试入口。源码链接用于核验当前实现，不表示稳定的外部 API；稳定插件入口是 `plugin-api` 与 `server-plugin-api`。

本手册基于当前仓库编写，核验日期为 **2026-10-19**。本次实际执行的检查及未执行项见[验证记录](verification.md)。操作背景用于解释代码可观察行为，“自检”是可重复执行的验收步骤，不表示本次已连接生产环境或实际调用模型。

这些模块文档在 GitHub 仓库阅读，不自动进入 npm 包；npm 随包参考仍是 `docs/config.md` 和 `docs/plugins.md`。安装方式见[安装页](install.html)，Docker 布局见 [Docker 指南](../docker/README.md)，开发交付门槛见[开发检查](development-checks.md)。
