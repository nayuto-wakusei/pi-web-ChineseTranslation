# 会话与协作

[返回文档目录](../maintenance.md) · 前置：[维护者上手](../getting-started.md)

## 维护契约

**职责**：协调 Pi runtime、消息/队列、历史树、归档与委派；不把运行时迁到 Web，也不让组件直接持有跨会话业务状态。

主链：SessionController → sessionApi → sessionProxyRoutes → sessionRoutes → PiSessionService → SDK；命令由 SessionCommandService 分派，事件经 SessionEventHub 回推。先找具体子服务，不默认在巨大的 PiSessionService 或 PiWebApp 中加逻辑。

| 修改面 | 必须保持 |
| --- | --- |
| 启动/切换 | 临时 ID 转正式 ID 保留待发内容；await 后核对机器与选择身份 |
| 消息/队列 | 已接收、排队、已消费和活动状态分离；取消不回滚工具副作用 |
| 历史读取 | 保留 SDK selected leaf，包括读取期间导航；latest 分支外部追加仍可刷新 |
| 命名/事件 | 统一 /name 路径，事件更新列表，不偷换选中会话 |
| 归档/删除 | 归档只读；批量报告部分失败，不把请求已受理当完成 |
| 委派 | 独立 spawn 与 tracked child 语义不同；保留父身份、cwd 与管理上下文 |

复现异步问题时用可控制 Promise，在请求未完成期间切机器/会话，再断言旧响应不覆盖新状态。树导航同时覆盖内存 leaf 和磁盘追加，不只测正常恢复。会话服务、工具和审计的改动均要求重启 daemon；仅浏览器状态改动通常只走 UI 重载。

## 启动与恢复

普通与完整特权管理会话在 Pi 1.3.0 下通过 SDK 内置工厂加载 MCP、codemode 和 tool-search，仍遵循 Pi 的扩展禁用设置与项目信任。受限管理保持原有受控资源路径，不加载这些工厂。`ask_user` 与 `yield_to_subsessions` 只能由模型直接调用，不能嵌入 codemode 脚本结束外层运行；嵌套工具事件归父结果，不生成重连后消失的独立聊天行。

会话运行在 daemon 中，而非浏览器标签页中。选定机器、项目和工作区后新建会话，检查模型与思考等级，再发送任务。首次启动可能涉及项目资源加载、模型准备和扩展问题；应查看活动状态和问题卡片，不要重复点击新建。

启动期间界面可先显示临时会话。此时发送的内容由客户端暂存，后端准备好后按顺序投递。临时行不等于已持久化的会话，也不能把还没送达 daemon 的内容视为刷新后必然可恢复的数据。

恢复已有会话保留其模型和思考等级；“新会话默认值”不会覆盖恢复状态。显式目标（包括记忆中未在可见列表展示的 agent 子会话）与自动可见候选回退分开，不因子会话被隐藏就替换明确选择。浏览器插件加载与对话消息恢复独立，插件切换不重新加入身份未变的归档会话。关闭浏览器或仅重启 Web/API 不主动终止 daemon 内的工作，但 daemon 重启不承诺继续原来的模型请求或 shell 进程。

会话定位使用完整、区分大小写的精确 ID，不接受缩写或前缀匹配。机器、cwd 和普通/管理作用域仍是身份的一部分；完整 ID 不能替代这些归属条件。HTTP 与 WebSocket 的历史/活动快照保留分支及连接世代，旧读取不能覆盖较新的导航或实时状态。

## 消息、队列与附件

流式生成期间可以选择引导当前工作（`steer`）或排到后续处理（`followUp`），实际消费时机由运行时决定。队列展示不等于模型已处理；清空队列只移除尚未消费的消息，不撤回已经执行的工具副作用。

逐条移除、编辑和切换队列类型需要目标机器的 `sessions.queueMessageActions` 能力。旧机器隐藏这些控件，发送与清空保持原行为。请求携带 `expectedQueue` 和所选 `index`，服务端比较队列的 `kind`/`text` 结构并额外核对所选项的附件存在标记；冲突时刷新后重新确认。该契约没有 revision 或条目 ID，无法识别同形旧消息消费后重新入队的 ABA，也不校验附件 payload 身份，不能宣称强身份 CAS。

Recall 将所选消息及其后续队列项移除，只把文本带回输入框；可能丢失附件时先确认。它不撤回已消费的消息，不将重建后的保留项重复计入管理审计。队列状态仍由 daemon 持有，输入框由浏览器持有，成功响应不应把旧会话文本填入新选择。公开请求类型见 [apiTypes.ts](../../src/shared/apiTypes.ts)，实现归属见 [queuedMessageMutation.ts](../../src/server/sessions/queuedMessageMutation.ts)。

使用停止按钮中止当前活动；它不是删除历史，也不等于重启 daemon。HTTP `abort` 与 `stop` 是不同操作，集成方不能用关闭连接替代明确的取消请求。

输入框草稿、待发送附件和 daemon 已接收的队列属于不同状态。切换会话后应核对输入内容和附件，不要把临时附件当永久上传。附件的内联/落盘差异见[文件与附件](files-terminals.md)。

提示词补全入口包括命令、文件和模型引用。`#provider/model-id` 表达模型引用，不会自动切换当前会话模型。具体键盘行为与补全限制见[配置参考](../config.md#prompt-completions)；自定义快捷键以设置页显示为准。

## 命令与历史树

常用已实现命令：

| 命令 | 用途与注意事项 |
| --- | --- |
| `/name <名称>` | 设置显示名称，空白名称拒绝 |
| `/session` | 查看消息、工具调用、token 与费用统计；不是账单结算证明 |
| `/compact [说明]` | 请求压缩上下文，开始提示不代表压缩完成 |
| `/reload` | 空闲时重载 Pi 资源，不重启 daemon 或服务端插件 |
| `/tree` | 浏览/导航当前会话树 |
| `/fork` | 从用户消息选择分叉位置，创建另一会话 |
| `/clone` | 从当前位置复制会话 |

**命令出现在补全目录不等于 Web UI 实现了全部 Pi CLI 行为。** 服务端明确处理上表命令，其他命令可能由客户端或扩展处理，也可能返回“Web UI 尚未实现”。尤其不要仅凭命令名存在就承诺 `/share`、`/export` 或 `/import` 可用。

树导航改变当前上下文位置，不是简单滚到某条消息。分叉与复制产生新会话，而不是创建 Git 分支或工作树。进行这些操作前等会话空闲；若树快照已过期，重新打开树后操作。未摘要的分支导航和 reset-to-root 都可能只改变内存状态。空闲 transcript 刷新必须保留 SDK selected leaf，不能以磁盘尾部替换当前分支；导航在异步磁盘读取期间完成也必须保留。runtime 位于最新 entry 时，仍须支持外部追加的刷新。

Session-list 组件只处理菜单交互，重命名修改交给 `SessionController`，复用 `/name` 命令路径。仅允许已持久化且未归档的会话，输入先 trim，再拒绝空白名称。对非当前行重命名不应切换正在阅读的对话；`session.name` 事件同步列表与选中会话元数据。

## 聊天布局不变量

聊天 transcript 的滚动容器拥有可见位置与耐久锚点，外层布局提供有界可用高度。长记录必须能滚到末尾；向前分页、加载提示增减、活动变化、图片加载和内容增强不能破坏正在阅读的位置。用户位于底部时继续跟随，主动离开底部后不因新输出强拉回末尾。dock、图片查看器和导航不是 transcript 滚动的修正器。布局与滚动入口见 [ChatView.ts](../../src/client/src/components/ChatView.ts) 和 [chatScrollPosition.ts](../../src/client/src/chatScrollPosition.ts)。

未读确认同时需要正确机器/分支、可见与聚焦状态，以及已加载且已渲染范围覆盖目标未读区间。首屏就绪或请求完成本身不足以确认整段已读；分页尚未覆盖未读区间时不能提前清除。

## 搜索、置顶与清理

通过会话搜索找名称或内容，结合机器、项目、工作区确认命中目标。置顶和未读是导航辅助状态，不改变模型上下文。完成通知、会话警告和浏览器错误也不是同一类记录，详见[状态与通知](../admin/operations.md)。

| 操作 | 效果 | 风险 |
| --- | --- | --- |
| 归档 | 将会话移入归档，可查看并恢复 | 归档视图只读，不在其中继续发消息 |
| 连同后代归档 | 处理父子树中的相关会话 | 确认范围，避免带走仍要使用的后代 |
| 恢复 | 将归档会话恢复为可继续使用的会话 | 仍依赖可用工作区与模型认证 |
| 删除已归档 | 永久移除相应归档记录/内容 | 不可当作可撤销的隐藏操作 |
| 按时间清理 | 预览后批量归档/删除 | 先看数量和范围，保留备份 |

清理的 `archiveIdleDays` 按会话修改时间，`deleteArchivedDays` 按归档时间；繁忙会话会跳过。预览到执行之间状态可能变化，应以执行返回的成功/失败结果为准。批量操作可能部分成功，不要只看一个总提示。

“脱离父会话”移除父子关联及 agent 子会话分类，不是复制、合并或删除聊天内容；归档会话不支持此修改。多个机器存在同 ID 时也只应更新发起操作的机器。

## 独立会话与受跟踪子会话

| 工具 | 使用场景 | 工作目录与结果 |
| --- | --- | --- |
| `spawn_session` | 发起独立任务 | 同项目工作区；结果不自动回传发起者 |
| `spawn_subsession` | 分解当前任务、汇总结果 | 固定父 cwd，记录父子关系 |
| `list_subsessions` | 查看已跟踪任务 | 返回状态摘要 |
| `check_subsession` | 完成后取最近结果 | 工作中不暴露部分输出 |
| `read_subsession` | 有目的地查看完成记录 | 可过滤、搜索和分页 |
| `yield_to_subsessions` | 汇合点等待 | 单独作为批次最后动作；完成会唤醒父会话 |

两个 spawn 都支持精确 `provider/model-id`，省略继承父模型，思考等级按模型能力调整。跟踪子会话没有 `cwd` 参数；换工作树不是它的用途。能力由机器 `spawnSessions`/`subsessions` 控制，后者还依赖前者。不要用高频轮询替代完成通知。

完成结果通过 daemon 的持久 inbox 协调交付，仍须核对父会话与当前上下文；通知不等于用户已读。导航里的子会话分组依赖服务端验证的双向精确关联，不把客户端标签或单向 metadata 当作父子关系证明。显式 ID 导航与自动选择候选分开，自动归档/删除后的选择不得落入隐藏的折叠子组。

## 问题与扩展对话框

`ask_user` 显示一个或多个问题，支持选项与自定义文字，也可不回答。调用发布问题后结束当前 run，回答以唤醒会话的后续消息交付，不是一个长期悬挂的工具调用；应单独作为最后动作，不重发或轮询。普通新消息会取消开放表单，新表单替换旧表单。问题及已回答/取消结果写入会话历史，浏览器重新读取历史可恢复展示；服务端按当前历史有效性处理回答，不能从历史卡片重新提交已失效回答。

Pi 扩展的确认、选择和输入以独立卡片出现，包含启动阶段。回答走独立通道，不排在提示词之后；多标签页最先回答生效，超时或中止使旧卡片失效。已回答卡片的浏览器本地展示不保证刷新后保留。支持三类对话框不等于支持任意 Pi 自定义 UI。

## 故障定位与自检

1. 没有输出：先看是否启动中、等待问题、排队、压缩或工具执行，再看模型认证，最后检查 daemon；不要先重启。
2. 刷新后历史不同：区分导航分支、未发送草稿和已持久化消息；确认机器及会话身份。
3. 操作提示只读：确认是否归档。需要继续时先恢复，不要直接修改归档文件。
4. 子会话无结果：检查是否仍在工作、是否受跟踪子会话，以及工具开关和管理模式显式拒绝。

部署后用测试会话验收：发送短任务、刷新恢复、重命名非当前行、搜索、置顶、归档后尝试发消息并恢复；另用无重要内容的会话测试树/清理。真实模型调用可能产生费用，不能用单元测试替代这一步。
